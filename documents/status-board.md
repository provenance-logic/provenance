## Right now

**Stage:** Stage 5 (Pre-launch sweep) — `v0.1.0-osr` is **gated on B-061** now, not just polish.
**Active OSR blockers:** **1** — [B-061](bugs/open.md#B-061) (cross-org information leak; three confirmed endpoints serve other-org data when the caller passes a different orgId in the URL, plus a likely cross-org write side effect on the trust-score path). Provenance's whole story is multi-tenant; we cannot tag a release with this open.
**Open High-severity bugs:** **1** — B-061.
**Open Medium-severity bugs:** **2** — B-011 (OPA amd64-only on Apple Silicon), [B-060](bugs/open.md#B-060) (last remaining piece: wire `demo-smoke-test.sh` + `seed:verify:soft-reset` into CI; both halves of the bug closed via #137 and #138).
**Open Low-severity bugs:** **10** — B-029, B-023, B-024, B-001, B-002, B-003, B-005, B-006, B-007, B-008.

**Headline from the 2026-05-21 session.** Closed both halves of B-060 — PR #137 repaired `softReset` against the live schema and added a `seed:verify:soft-reset` CLI verifier; PR #138 rewrote `demo-smoke-test.sh` layers 3–6 against the real org-scoped routes (with a behavioral RLS check instead of a phantom `/rls-probe` endpoint, applying the same B-050 reasoning). What the session also surfaced, while probing endpoints to choose the layer-5 replacement: at least three org-scoped endpoints (`/governance/dashboard`, `/governance/effective-policies`, `/products/:id/trust-score`) return another org's data to an authenticated caller from a different tenant — and the trust-score path appears to commit a write side effect. Filed as B-061.

**Most concerning: B-061.** Cross-org information leak in a platform whose differentiation is multi-tenancy. Three endpoints confirmed leaky, likely several more (every controller using `@Param('orgId')` directly instead of `ctx.orgId` is a candidate). Root cause is dual: some controllers pass URL `:orgId` straight through, and the RLS session variable is set with `is_local=true` on a fresh pool connection that releases before the service-layer query acquires its own. Short-term fix is an `OrgScopeGuard` (compare `@Param('orgId')` to JWT claim at the controller boundary, 403 on mismatch); long-term is RLS-by-default. See B-061 for the full analysis and the smoke-test regression hook that should ship with the fix.

## Up next (priority order)

1. **B-061 — close the cross-org leak.** OSR-blocking. Recommended sequencing:
   - **PR 1: controller-boundary guard.** New `OrgScopeGuard` (or extend `JwtAuthGuard`) that compares `request.params.orgId` to `request.user.orgId` and returns 403 on mismatch. Small diff, immediately stops the bleed. Ship with an integration test that the cross-org calls now 403, plus a new smoke-test layer that exercises the cross-org path against every org-scoped controller.
   - **PR 2 (follow-on): RLS-by-default.** Fix `OrgContextMiddleware` so the `provenance.current_org_id` session variable persists across the connections the request actually uses (the current `is_local=true` on a transient pool connection is the structural reason RLS doesn't catch the bug today). Bigger refactor, deserves its own design pass.
   - **B-060 CI integration** comes next and naturally takes the cross-org regression check with it.
2. **B-060 — CI integration (last piece).** Wire `demo-smoke-test.sh` and `seed:verify:soft-reset` into a workflow that runs on every merge to main. With the cross-org regression check from above bundled in.
3. **Stage 5 polish** — README polish · doc link-check · "you are here" doc nav · clean-checkout smoke-test · status badges · tag `v0.1.0-osr` + release notes. Doc-link-check scaffolding is half-done on a stashed branch (`ci-doc-link-check`). **Cannot tag `v0.1.0-osr` until B-061 is closed.**
4. **B-011 — multi-arch OPA image.** Bigger jump than the entry suggests (OPA 1.x defaults to Rego v1; bootstrap policy at `infrastructure/docker/config/opa/policies/health.rego` is v0 syntax; the platform's governance policy compiler also needs an audit). Apple Silicon contributors run under amd64 emulation today — functional, slow, cosmetic warning at first run.
5. **Demo environment hardening follow-ups** — production-mode demo images (closes the B-051/52/53 architectural family) + `demo-bootstrap.sh` health-check timeout (the silent-failure pattern that hid B-045 for weeks).
6. **Low-severity backlog** — B-029 (Vite HMR bind-mount staleness), B-023/B-024 (F7.7 role-assignment forward-compat seams), B-001–B-008 (the long tail of small UI/UX rough edges).
7. **(Post-launch, "no shame" deferrals)** F7.29 SLA escalation · F7.42 Human Review Queue · 5.5 Anomaly Detection · 5.7 SOC 2 Foundations · Phase 6 managed-AWS · "sexy" public landing page · demo production-mode images.
