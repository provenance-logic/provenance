**Open Low-severity bugs:** **10** — B-029, B-023, B-024, B-001, B-002, B-003, B-005, B-006, B-007, B-008.

**Headline from the 2026-05-21 session.** Three-PR run closed every active blocker:
- PR #137 — repaired `softReset` against the live schema, added `seed:verify:soft-reset` CLI verifier (B-060 part 1).
- PR #138 — rewrote `demo-smoke-test.sh` layers 3–6 against real org-scoped routes; behavioral tenant-isolation check replaced the phantom `/rls-probe` endpoint (B-060 part 2).
- PR #139 — filed B-061 after the smoke-test rewrite surfaced a cross-org information leak on `/governance/dashboard`, `/governance/effective-policies`, and `/products/:id/trust-score`.
- This PR (B-061 fix) — extended `JwtAuthGuard.canActivate` with a `request.params.orgId === request.user.orgId` check that throws 403 on mismatch. Five new unit tests, plus a new smoke-test layer that asserts cross-org URLs return 403. Verified live: the three previously-leaky endpoints now reject; previously-safe endpoints unchanged.

**What's left.** B-062 covers the structural follow-up: `OrgContextMiddleware` uses `set_config(..., is_local=true)` on a transient pool connection, so the RLS session variable doesn't actually defend most service-layer queries. With B-061's guard in place, the platform's tenant isolation is enforced **at the controller boundary only** — if the guard ever has a bypass, RLS won't catch it. B-062 is the design-pass work to make RLS-by-default actually work; deferred because the leak it would have caught is already closed.
