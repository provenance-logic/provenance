## Right now

**Stage:** Stage 5 (Pre-launch sweep) — heading toward `v0.1.0-osr`.
**Active OSR blockers:** **1** — [B-054](bugs/open.md#B-054) (notification click silently grants access; correctness + governance implication, not UX). The "zero OSR blockers" claim from earlier today was retracted after the investor-demo rehearsal turned up B-054 plus four UI-completeness bugs (B-055, B-056, B-057, B-058) that all break the curated demo flow.
**Open High-severity bugs:** **1** — B-054.
**Open Medium-severity bugs:** **4** — B-011 (OPA amd64-only on Apple Silicon), B-055 (no inline approve/deny on access-request notification), B-056 (logout 404), B-057 (no agent detail page).
**Open Low-severity bugs:** 12 — B-058 (new), B-050, B-029, B-023, B-024, B-001, B-002, B-003, B-005, B-006, B-007, B-008.

**Headline from the investor-demo rehearsal:** Matt walked the investor demo script solo against the live seeded demo and **could not get past Step 4** without workarounds. Five distinct bugs surfaced ([#123](https://github.com/provenance-logic/provenance/pull/123) files B-054 through B-058). The pattern is honest: the *contracts* are right (Phase 4 MCP server live, Domain 12 connection-reference enforcement default-on, F7.46 onboarding wizard shipped) but the **UI surface has not caught up to the contracts in two specific areas** — notification → action wiring (B-054, B-055) and the agent detail surface (B-057). Plus one auth-flow rough edge (B-056) and one seed-data gap (B-058). The Phase 4 ✅ checkmark is still defensible at the API level; the demo-readiness story isn't.

**The most-concerning single bug** is [B-054](bugs/open.md#B-054): clicking a pending-access-request notification silently grants the access without the recipient ever reaching an approval UI or pressing an Approve button. The audit log records an `access_granted` event with no corresponding human approval gesture. This invalidates the platform's "approval requires explicit, audited intent" claim in a way that would fail SOC 2 access-control evidence in production. Fix it first.

## Up next (priority order)

1. **B-054 — fix the silent auto-grant on notification click.** Correctness bug, not UX. Reproduce in dev tools network panel to identify which endpoint the click handler invokes; separate "read notification" from "act on resource" cleanly. Add a regression test that asserts no `access_grant` row is created from a notification read action alone. This is the only true OSR blocker in the set.
2. **B-057 — build the agent detail page.** Biggest demo gap by impact (affects all three audience scripts). Backend has the data — `GET /agents/:id`, `/access?principalId=...`, the connection-reference endpoint from Domain 12. Frontend just hasn't been built to assemble them. Minimum viable: identity fields + tab strip with Access Grants, Connection References, Audit Trail. 1–2 days of frontend work.
3. **B-055 — wire the access-request notification to a working approval path.** Gated on B-054 being fixed first (otherwise the deep-link MVP path itself triggers the bug). Smallest acceptable diff: render the existing seeded `deepLink` as a primary CTA so clicking lands on the proper approval UI.
4. **B-056 — fix logout flow from authenticated routes.** Set the post-logout `redirect_uri` in the Keycloak `provenance-web` client and add a frontend route guard. Both fixes; either alone leaves the other class of paths exposed.
5. **B-058 — add `governance@acme.example.com` recipient to the trust-score-drop seed notification.** Trivial. Use `seedKey: 'acme:governance:trust:revenue-daily'` for idempotency.
6. **Verify `demo-reset.sh --hard` end-to-end** on the started-but-state-consumed demo box. Was Up next #1 before the rehearsal; bumped down because demo-flow correctness now precedes demo-reset workflow. Still needed before the next end-to-end demo. Hypothesis: `aws ec2 start-instances` (~2 min) + `demo-reset.sh --hard` (~30–60 sec) produces pristine state in ~3 min vs ~30 min for terraform destroy/apply. If verified, update `documents/runbooks/demo-environment.md`.
7. **B-050 fix** — smoke-test layer 2 step 3 calls a non-existent `/organizations/me` route. Path 1 (update the smoke test) is the smaller diff. Unblocks smoke-test layers 2.3 + 3 + 4 + 5 + 6 running end-to-end as a CI / pre-demo gate.
8. **Smoke-test layers 3–6 against the prod-cert demo cycle.** Gated on B-050.
9. **Stage 5 polish** — README polish · doc link-check · "you are here" doc nav · clean-checkout smoke-test · status badges · tag `v0.1.0-osr` + release notes. Doc-link-check scaffolding is half-done on a stashed branch (`ci-doc-link-check`).
10. **Demo environment hardening follow-ups** — production-mode demo images (closes the B-051/52/53 architectural family) + `demo-bootstrap.sh` health-check timeout (the silent-failure pattern that hid B-045 for weeks).
11. **(Post-launch, "no shame" deferrals)** F7.29 SLA escalation · F7.42 Human Review Queue · 5.5 Anomaly Detection · 5.7 SOC 2 Foundations · Phase 6 managed-AWS · "sexy" public landing page · demo production-mode images.

- ✅ Persistent EIP `34.204.222.196` tagged `provenance-demo-eip`; Cloudflare A records permanent
- ✅ Persistent Caddy-data EBS volume `vol-0fd2383ae142d2c95` (1 GB gp3, us-east-1c) — survives `terraform destroy`
- 🛑 Demo instance `i-0669a177766d2a29e` — stopped (not destroyed) after Matt's rehearsal. State on disk reflects what Matt clicked through during the demo: read notifications, approved (or accidentally-approved-via-B-054) access requests, anything else he interacted with. **Cost ~$0.10/day stopped vs ~$0.16/hour running.**
- ✅ Real Let's Encrypt prod certs in the persistent EBS volume — `demo.provenancelogic.com` and `auth-demo.provenancelogic.com`, valid through 2026-08-15. Survives stop/start and survives terraform destroy/apply.
- ⚠️ **The demo as it sits today cannot be re-run cleanly without addressing B-054, B-055, B-057.** The flow Matt walked was the *intended* investor script — but it broke partway through. A pristine-state reset alone doesn't fix that; the bugs themselves need to land first.

**Restart procedure** (for the next end-to-end attempt):

1. Land at least B-054, B-055, B-057 first (or accept the demo workarounds documented in inventory Section 11 — see PR #125).
2. `aws ec2 start-instances --instance-ids i-0669a177766d2a29e` — wait ~2 min, confirm `https://demo.provenancelogic.com/api/v1/health` returns 200.
3. Pull main on the demo box (`cd /opt/provenance && git checkout main && git pull`) and rebuild any containers whose code changed.
4. Reset to pristine state with `bash infrastructure/scripts/demo-reset.sh --hard` (~30–60 sec). **Still not end-to-end verified — see Up next #6.**
5. Run the demo. Stop the instance when done.
