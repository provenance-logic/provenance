## Demo environment — current state

- ✅ Persistent EIP `34.204.222.196` tagged `provenance-demo-eip`; Cloudflare A records permanent
- ✅ Persistent Caddy-data EBS volume `vol-0fd2383ae142d2c95` (1 GB gp3, us-east-1c) — survives `terraform destroy`; **architecture end-to-end proven in production**
- 🛑 Demo instance `i-0669a177766d2a29e` — being stopped (not destroyed) at end of session. State preserved on disk; next `aws ec2 start-instances` brings up the same box with same data, certs, and seed in ~2 min. **Cost ~$0.10/day stopped vs ~$0.16/hour running.** **Important caveat:** the state is *exactly* as Matt left it — including notifications he read, requests he approved, classifications he changed. The demo script in `documents/demo-scripts/demo-asset-inventory.md` relies on specific unread/pending signals; running the script a second time without a reset will find those slots already actioned. See "Up next" #1.
- ✅ All B-051/52/53 fixes on main. Demo box's `/opt/provenance` is on `fix-keycloak-demo-redirect-uri` branch, which is content-equivalent to main (both #117 and #118 squash-merged from it). When demo is next started, a `git checkout main && git pull` will rejoin trunk cleanly; not strictly required since the content is identical.
- ✅ Real Let's Encrypt prod certs in the persistent EBS volume — `demo.provenancelogic.com` and `auth-demo.provenancelogic.com`, valid through 2026-08-15. Survives stop/start and survives terraform destroy/apply.
- ✅ Seed completed end-to-end. Asset inventory of what's seeded lives in `documents/demo-scripts/demo-asset-inventory.md`.
- 🔲 Smoke-test layer 2.3 trips B-050; layers 3–6 not yet exercised.

**Restart procedure** (when ready for next demo):

1. `aws ec2 start-instances --instance-ids i-0669a177766d2a29e` — wait ~2 min, confirm `https://demo.provenancelogic.com/api/v1/health` returns 200.
2. **If repeating the demo against the same script:** `ssh -i ~/.ssh/provenance-demo ec2-user@demo.provenancelogic.com 'cd /opt/provenance && bash infrastructure/scripts/demo-reset.sh --hard'` — destroys all data and re-runs the seed (~30–60 sec). Pristine state restored. **This is not yet end-to-end verified on this cycle** — see "Up next" #1.
3. **If exploring or doing one-off work** where state continuity is fine: skip step 2; the data persists across stop/start.

Per-cycle cost: stop/start lifecycle is ~$0.10/day idle, ~$0.16/hour active. The previous "destroy/recreate per demo" pattern was ~$0.08 per cycle but ~30 min slower and lost the cert state. The stop/start + reset approach trades a tiny ongoing cost for ~10x faster repeat cycles.
