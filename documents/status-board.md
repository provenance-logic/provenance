**Last updated:** 2026-05-25 (late). **Headline — honest status correction: the platform is NOT OSR for connector self-service, and `v0.1.0-osr` overstated readiness at the connector layer.** This is Matt's assessment at end-of-session, and it is correct. The session set out to polish connector registration and instead exposed that it was never actually self-service: the credential step required either a pre-staged AWS Secrets Manager ARN or the `local-env:` env-var sentinel — both demand operator/shell access a domain owner does not have. **[ADR-013](architecture/adr/ADR-013-connector-credential-self-service-vault.md) (#220)** closed that *mechanical* gap — a masked secret field in the GUI, vaulted with AES-256-GCM (reusing the Domain 10 `EncryptionService`), stored as a `vault:<uuid>` reference, never persisted in plaintext / logged / returned; built-in encrypted store is the default so self-hosted needs no AWS. Plus **B-079 (#221)** — the vault entity was in `forFeature` but missing from the root `entities[]`, so every credential save 500'd (2nd occurrence of that exact pattern — see resolved.md) — and a stuck-"Refreshing…" validate-message UX fix **(#222)**. All merged and deployed to dev. **But the deeper miss stands:** getting a Snowflake connector to actually *authenticate* took a multi-round wrestling match with Snowflake network policies / authentication policies (`390432 "Network policy is required"`), resolved only via a dedicated-service-user + network-policy recipe — expert work no domain owner would complete unaided. **As of this break the dev Snowflake connector is still not green** (last error `394400 "Programmatic access token is invalid"` — likely a token-entry issue, unresolved). Net: connector registration is now *mechanically* self-service (paste a secret), but end-to-end onboarding — especially Snowflake PAT prerequisites — is **not OSR-smooth**. Tracked as **[B-080](bugs/open.md#B-080)**. The recurring lesson this whole session (B-076, B-077, the `local-env` dead-end, B-079, the Snowflake PAT saga): **"✅ Complete" / "OSR" claims kept meaning "passes its own tests / works on a curated path," not "a real user can do it unaided."**
